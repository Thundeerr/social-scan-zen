# Fanvue analytics connection

App: Kiikii HQ Analytics. Owner-only setup in `/business`; hard-bound to Fanvue creator `kiikiixoxo`.

Register callback `https://instascanner.app/api/public/fanvue/callback`. App scopes: `read:self`, `read:insights` (other configured scopes are not requested). Copy the client secret directly into the password field in `/business`. It is never returned to the browser after storage. Do not paste it into chat, logs, Git or a ticket. If it was not saved when the app was created, the owner must reset it in Fanvue; no automated reset is performed.

Deploy migration `20261027192120_fanvue_analytics_connection.sql` and app together. Existing Supabase Vault is required. No worker change. No generation or publishing actions.

Tokens and client secret are stored encrypted using Vault. Only service_role can use the credential RPCs or connection/state tables. Authentication is revalidated with getUser and the allowed owner ID. PKCE uses server-side verifier, hashed one-use state, 10-minute expiry, Secure/HttpOnly/SameSite=Lax browser binding. Fixed callback and API endpoints. OAuth credentials use Basic authentication. Distributed leases serialize connection updates and sync. Before a refresh, refresh_pending is persisted; a lost/failed refresh requires reconnect instead of replaying a single-use token. Tokens rotate together before use. Disconnect clears locally stored tokens but retains app credentials; revoke app authorization in Fanvue to revoke remote grants.

Daily reconciliation starts at 19:55 Europe/Berlin through the existing report cron; retries at most every 10 minutes. A successful evening sync suppresses further automatic fetches that day. Manual fetch also has a ten-minute cooldown. Earnings are fully cursor-paginated (constant size 50), capped at 100 pages/120 seconds. Partial/invalid responses do not replace snapshots. Current month and today use Berlin calendar boundaries. API amounts are USD cents even if currency records another original currency. Negative refunds/chargebacks/deductions are summed. appStore purchases are not revenue. Subscription first-payment count is NOT a count of distinct new subscribers. Profile fanCounts is the current subscriber/follower stock, not a period's acquisitions. Historical manual snapshots are preserved, API data is a separate source. Timestamp and errors remain visible; no claim of realized profit.

Validation: `npm test -- src/lib/fanvue-analytics.test.ts src/lib/business-report.test.ts src/lib/business-report.server.test.ts`; `node tests/fanvue-analytics-db.mjs`; `node node_modules/typescript/bin/tsc --noEmit`; `npm run build`. DB tests mock Vault (not a crypto test); verify production uses actual Vault. Check callback rejects missing state/cookie, then connect as owner with Fanvue consent. Fetch and compare full month net/gross with earnings ledger, accounting for reversal treatment (Fanvue summary excludes rather than nets some reversals). Never show 0 for a missing count.
